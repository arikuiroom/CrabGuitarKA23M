# 構成と更新手順

## 全体像

依存ライブラリやバックエンドを持たない静的 Web アプリです。ブラウザが UI を表示し、ユーザー操作を Web Audio API の発音へつなぎます。音源ファイルのダウンロードやマイク入力はありません。

- `src/app.js`：弦の当たり判定、コード選択、色の切り替え、アーム、消音、音に連動する動き
- `src/audio.js`：波形合成、弦ごとの発音管理、音色、残響、出力レベルと消音
- `src/style.css`：画面配置、縦横画面、動き、操作時のスクロール抑制
- `public/index.html`：日本語 UI、SVG の構造、画像のマスク、ボタン
- `public/kani.png`：基準となる原画
- `public/sprites/`：5 色の描画済み PNG
- `public/manifest.webmanifest`、`public/app-icon.svg`：ホーム画面表示用の情報とアイコン
- `scripts/`：ビルド、ローカルサーバー、検証用の処理
- `tests/audio/`：Node.js で実行する音源・リソース管理の回帰テスト
- `tests/browser/`：実際の Web Audio と DOM を使うブラウザ検証ページ
- `dist/`：`npm run build` で生成する公開用ファイル。直接編集しない

ビルドは `public/` の内容と `src/app.js` / `src/audio.js` / `src/style.css` を `dist/` にコピーします。トランスパイルやバンドルは行いません。

## 演奏入力

### 弦とコード

`src/app.js` の `bases` が 6 弦から 1 弦までの基準周波数、`chords` がフレット数です。`null` の弦はそのコードでは鳴りません。

- 基準音：E2 / A2 / D3 / G3 / B3 / E4
- UI の選択肢：`open` / `C` / `G` / `Am` / `Em`
- 物理弦のインデックス：`0` が 6 弦、`5` が 1 弦
- キー `1`〜`6`：このインデックス順に低い弦から演奏
- 原画の弦、補助パネル、キーボードは同じ弦インデックスを使う

コード変更はすでに鳴っている弦を止めず、次に弾く音へ反映します。色変更も発音中のソースを止めず、共有の音色設定を滑らかに変更します。

### 当たり判定と優先順位

`instrumentPosition()` は `getScreenCTM()` の逆行列でポインター位置を SVG 座標へ戻します。回転や拡大縮小後も、表示された弦と操作位置が一致するための仕組みです。CSS の画面座標だけで別の当たり判定を作らないでください。

`attach()` はポインターごとに状態を持ち、押下・移動・解放・キャンセルを処理します。通常の弦横断はその都度発音し、現在はストローク速度によるカッティング判定を行いません。

- アーム操作中は新たな弦の発音を抑え、すでに鳴っている音だけを曲げる
- アームは最大 ±4 半音。解放・キャンセルで 80ms かけて元へ戻す
- 大きなハサミを押さえると、押している間の新規発音を抑えて消音する
- ハサミから手を離しても、消した音を復活させない
- ヘッド寄りのハーモニクスは、短時間かつ移動の小さいタップを解放時に判定する
- ウィンドウのフォーカス喪失やページ非表示時は、ポインターとアームを戻して消音する

ハサミの対象領域は原画座標の中心 `(390, 420)`、半径 `(120, 105)` の楕円です。見えないのは案内表示であり、操作領域は有効です。

## 音源

### 合成と 5 音色

`src/audio.js` は減衰する倍音と短い励振成分から波形を生成し、キャッシュして再利用します。実録音を使ったサンプラーではありません。

- `GUITAR_PRESETS`：各色の EQ、歪み、出力、残響量
- `PLUCK_TIMBRES` / `synthesizeTimbre()`：スチール、ナイロン、ウクレレ風の発音と減衰
- `synthesizeHarmonic()`：赤・ミント・黒の、柔らかく立ち上がるハーモニクス
- `synthesizeNylonTouch()`：焦茶の短い木質の「ポクッ」という音
- `_pluck()`：実際の発音。ミントの短いワウも、各発音のフィルターで処理
- `getPlaybackFrequency()`：赤茶だけ 190Hz 未満の音を 1 オクターブ上げる

赤茶ではハーモニクス操作も通常音になります。色 ID は `red` / `mint` / `black` / `darkbrown` / `redbrown` で、UI・音源・画像ファイル名が対応しています。

### 同じ弦の弾き直し

`GuitarAudio.stringVoices` は弦ごとの現在の発音を追跡します。`pluck()` と `pluckHarmonic()` に弦インデックスを渡すと、同じ弦の前のソースを `STRING_RELEASE_TIME = 0.02` 秒で減衰させ、次の音は直ちに開始します。短いクロスフェード中は新旧のソースが重なりますが、各弦の現在の発音は一つです。

他の弦は止めません。すでに共有リバーブへ入った音は部屋の残響として自然に減衰します。弾き直しのために共有リバーブを消したり、弦ごとのリバーブを増設したりしない構成です。

まだ鳴っていない同時刻の古い発音は即座に停止・切断します。`liveVoices` は解放中も含むソースを追跡し、`onended` でソース・フィルター・ゲインを切断します。波形キャッシュは最大 48 件、旧 API を含む発音数には上限があります。

### 出力経路

通常音は「ソース → 発音ごとのフィルターとゲイン → 共有 EQ・歪み → ドライ音とステレオ残響 → コンプレッサー → 安全用波形処理 → 消音ゲート → 音量 → 出力」の順です。

ナイロンの短いタッチ音には残響へ送らない経路を使います。消音は最終出力を滑らかに下げてからソースと残響を止めるため、残響だけが急に切れるクリックを避けます。古い WebKit の `AudioParam` 処理に備え、ゲイン変化の状態も追跡しています。

互換性のため、音源には `cutStrum()` / `pluckCut()` と独立エフェクトの旧 API が残っています。現行 UI からは呼びません。これらのテストがあることは、現行の演奏機能を意味しません。

## 描画と動き

原画の形状を保ったまま、SVG のマスクで一つの大きなハサミと四本の小さな足を分けて動かします。ギター本体は安定した操作面として固定し、アームだけを別途回転させます。

色替えには事前に描画した `public/sprites/*.png` を使います。色を変えるたび、またはアニメーションの各フレームで大きな SVG 色フィルターを再計算しないための構成です。

`watchSound()` は最終音量を反映した出力 RMS を読み、`--flutter-amount` を更新します。音の立ち上がりで動きが大きくなり、余韻とともに小さくなり、無音では監視ループも休止します。`prefers-reduced-motion` では装飾アニメーションを止めます。

### 原画を扱うときの制約

カニギターの既存デザイン、比率、目、弦、金属部品、指板、一つの大きなハサミと四本の小さな足を維持してください。足やハサミを追加しないでください。新しい色を作る場合も、形状・金属・目・指板を変えるのではなく、既存の塗装部分を対象にします。

原画のサイズや位置を変えると、マスク、弦、アーム、消音領域の座標すべてに影響します。画像だけを差し替えて確認を省略しないでください。

## よくある変更

### コードを増やす

1. `src/app.js` の `chords` に 6 要素の配列を追加する
2. `public/index.html` に同じ `data-chord` ID のボタンを追加する
3. `src/style.css` のコードボタン配置を確認する
4. 6 本の音程、鳴らさない弦、押したままの選択、他の弦の余韻をテストする

### 色・表示名を変える

1. `public/sprites/` の対応画像を用意し、原画の形を維持する
2. `src/app.js` の `presets` で表示名と音色説明を合わせる
3. `public/index.html` の `data-preset`、色見本、`aria-label` を合わせる
4. 音色 ID を増減する場合は `src/audio.js` の `GUITAR_PRESETS` も更新する

`presets` の `rgb` 値だけを変更しても、描画済み PNG の色は変わりません。現在の 5 色を増やすときは、画像の先読み数とキャッシュの負荷も確認してください。

### 音色を調整する

EQ や歪み・残響量は `GUITAR_PRESETS`、弦そのものの質感は `PLUCK_TIMBRES`、ミントのワウは `_pluck()`、ハーモニクスは専用の合成関数を変更します。一度に変える範囲を小さくし、音量差に惑わされないように比較してください。

44.1kHz と 48kHz、通常音とハーモニクス、連打と複数弦を確認します。音程、減衰、出力ピーク、同じ弦の 20ms 解放、消音後の無音を保ってください。聴感の良さは数値テストだけでは判定できません。

### 配置を変える

`src/style.css` と `public/index.html` を変更します。CSS は後半のモバイル・横画面・standalone 用規則が先の規則を上書きするため、該当画面の最終スタイルを確認してください。

SVG の画面変換を使う当たり判定、ボタンの押しやすさ、画面端のアーム操作、セーフエリア、スクロール抑制を維持します。案内文だけなら `public/index.html`、演奏後の状態表示なら `src/app.js` も確認してください。

## 開発・更新の流れ

1. 更新用の Git ブランチを作り、目的を一つに絞って変更する
2. `npm test` を実行する
3. `npm run dev` で表示・操作・実音を確認する
4. `npm run build` と `npm run preview` で公開用の内容を確認する
5. `CHANGELOG.md` に変更内容を追記してコミットする
6. 公開する場合は `dist/` を使い、公開後にも実際の URL を開いて確認する

個別に調べる場合は `npm run test:audio` と `npm run test:build` を使います。`npm run verify:baseline` は初期の v18 基準版との一致を調べるための検証です。将来の機能変更で差が出るのは正常で、通常の更新で過去の基準を上書きするためのコマンドではありません。

ソースを GitHub に push しても、現在の公開サイトへ自動反映される構成ではありません。このリポジトリからの GitHub Pages 公開も有効化していません。ホスティングを変更する場合は、相対 URL、manifest、画像の読み込みを移行先で別途確認します。

## 手動確認チェックリスト

`npm run dev` を起動し、アプリは `http://127.0.0.1:8080/`、検証ページは `http://127.0.0.1:8080/tests/browser/` 配下で開きます。ブラウザの音声再生制限により、検証ページの実行ボタンなどを押す必要があります。

- [ ] 最初のタップから音が出る。6 本を一音ずつ弾ける
- [ ] ゆっくり／速い／往復ストロークで、横切った弦が通常音として鳴る
- [ ] 同じ弦の連打で前の音が消え、別の弦は残る
- [ ] コード変更と色変更だけで、鳴っている音が停止しない
- [ ] 5 色の画像と音色が対応し、ボタン操作で弦が誤発音しない
- [ ] 赤・ミント・黒のハーモニクス、焦茶の短い音、赤茶の通常音を確認する
- [ ] アーム保持中は新しい弦が鳴らず、解放・キャンセルで音程が戻る
- [ ] ハサミの非表示の消音領域、ミュート、停止、音量 0 が機能する
- [ ] 消音後に手を離しても古い音が戻らず、次の操作で再び鳴る
- [ ] 一つのハサミと四本の足が音の減衰に合わせて動き、無音で止まる
- [ ] 320px / 390px 程度の縦画面、横画面、広いデスクトップで操作できる
- [ ] ボタンや弦の操作でページがずれず、表示が画面外へ欠けない
- [ ] フォーカス喪失・復帰、タブ切り替え、連続演奏で異常がない
- [ ] コンソールにアプリ由来のエラーがなく、画像・JS・CSS に 404 がない
- [ ] 動きを減らす設定とキーボード操作で使える

### iPhone 実機

消音モード OFF で内蔵スピーカーから鳴ることは確認済みです。画面幅のエミュレーションと合成ポインターイベントだけでは、実機の音声出力、同時タッチ、OS のジェスチャーや長時間の発熱は確認できません。

更新時は実機の Safari とホーム画面からの起動、縦横切り替え、コードを押さえながらの演奏、アームと消音、スリープ復帰、長めの連続演奏を確認します。機種・OS・ブラウザ・音声出力先を記録すると、再現性を確かめやすくなります。
